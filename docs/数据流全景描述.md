# Spider_XHS 数据流全景描述

> 从用户点击"开始搜索"到最终下载 Excel 报告的完整数据流。

---

## 第一阶段：用户提交搜索请求

用户在 Web 界面输入关键词（如"巧克力"+"北欧"+"Fazer"），设置目标数量 200、爆款比例 0.5、最低样本量 60，点击"开始采集"。

前端发送 `POST /api/viral/search`，参数：
```json
{
  "keywords": ["巧克力", "北欧", "Fazer"],
  "target_count": 200,
  "viral_ratio": 0.5,
  "min_sample_count": 60,
  "note_type": 0,
  "time_range": 0
}
```

`viral_app.py` 收到请求后：
1. 生成任务 ID：`viral_20260414_153022_847`
2. 注册到 `task_status` 字典（状态 `running`，进度 `0`）
3. 用 `background_tasks.add_task()` 在后台启动采集
4. **立即返回** `{task_id, status: "started"}` 给前端
5. 前端开始轮询 `GET /api/viral/status/{task_id}` 获取进度

---

## 第二阶段：多关键词数量分配

后台任务 `collect_viral_notes_task` 启动，从用户数据中获取 Cookie，创建 `ViralNoteCollector`，调用 `search_viral_notes_multi_keywords()`。

**每个关键词的目标数量计算**（`_calculate_target_per_keyword`）：

```
base_per_keyword = 200 ÷ 3 = 66
raw_needed = 60 ÷ 0.5 = 120（逆算需要多少原始数据才能筛出 60 条爆款）
ideal_per_keyword = int(120 × 1.3 ÷ 3) = 52（加 30% 去重损耗）
upper_limit = max(66 × 1.5, 66) = 99
result = min(max(66, 52), 99) = 66
```

所以每个关键词目标采集 **66 条**。

---

## 第三阶段：三维度采集（核心采集循环）

对每个关键词，依次按三个维度采集：

| 维度 | sort_type | API 排序参数 | 目标 |
|------|-----------|-------------|------|
| 点赞 | 2 | `popularity_descending` | 22 条 |
| 评论 | 3 | `comment_descending` | 22 条 |
| 收藏 | 4 | `collect_descending` | 22 条 |

每个维度的目标 = `ceil(66 ÷ 3) = 22`。

### 3.1 搜索笔记列表

`_fetch_dimension` → `_search_notes_async` → `XHS_Apis.search_note()`

**签名生成链路**（每次 API 调用都走这条路）：
```
search_note(query, cookies_str, page, sort_type)
  → @guarded_api 装饰器包裹
    → generate_request_params(cookies_str, api_path, data)
      → trans_cookies(cookies_str) → 解析出 a1 字段
      → generate_xs_xs_common(a1, api_path, data, 'POST')
        → execjs 调用 xhs_xs_xsc_56.js 的 get_request_headers_params()
          → 内部: MD5(url+data) → mnsv2 混淆算法 → Base64 → "XYS_" 前缀 = xs
          → Date.now() = xt
          → JSON{a1, xs, xt, CRC32校验} → Base64 = xs_common
      → generate_xray_traceid() → execjs 调用 xhs_xray.js
    → 组装 Headers: x-s, x-t, x-s-common, x-b3-traceid, x-xray-traceid
  → requests.post("https://edith.xiaohongshu.com/api/sns/web/v1/search/notes", ...)
```

API 返回 `data.items`，每项含 `note_id` 和带 `xsec_token` 的笔记 URL。**每页固定 20 条**，最多翻 30 页。

### 3.2 获取每条笔记详情

对搜索结果中的每条笔记，调用 `_get_note_detail_async` → `XHS_Apis.get_note_info()`：

```
POST https://edith.xiaohongshu.com/api/sns/web/v1/feed
Body: {source_note_id, xsec_token, xsec_source: "pc_search"}
```

**限流重试逻辑**：
- 正常情况：最多 3 次尝试（初次 + 3 秒后 + 6 秒后）
- 如果 `items` 非空 → 调用 `handle_note_info(items[0])` 解析数据 → 返回
- 如果 `items` 为空（**软限流**，小红书不报错只返空）→ 等待后重试

**自适应降速**：
- 连续 3 次空结果 → 先尝试刷新 xsec_token（重新搜索同一页获取新 token）
- 刷新失败 → 暂停 60 秒（`RATE_LIMIT_PAUSE`）
- 暂停达 3 次 → 终止整个维度

**请求节奏控制**：
- 笔记间隔：**1 秒**
- 页间隔：**2 秒**
- 维度间冷却：**30 秒**（无副 Cookie）或 **3 秒**（有副 Cookie 轮换时）

### 3.3 数据解析（`handle_note_info`）

API 返回的原始 JSON 经过 `data_util.py` 解析成扁平字典：

```
原始 API 数据                          → 解析后
data.note_card.type                    → note_type: "图集" 或 "视频"
data.note_card.interact_info.liked_count → liked_count
data.note_card.image_list[i].info_list[1].url → image_list: [url1, url2, ...]
data.note_card.video.stream.h265[1].master_url → video_urls: [{url, priority:2, codec:"H.265"}]
```

**视频 URL 多源优先级**（priority 越小越优先）：
1. `origin_video_key` → CDN 直链
2. `h265[1]` 超清 1080p
3. `h265[1]` 备用 URL
4. `h265[0]` 标准 720p
5. `h264[0]` 最高兼容
6. `h264[0]` 备用 URL

## 第四阶段：去重、排序、筛选

三个关键词各采集完 3 个维度后，进入合并阶段。

### 4.1 按 note_id 去重

```python
if note_id not in all_notes:
    note['source_keywords'] = ["巧克力"]     # 新笔记：记录来源关键词
    all_notes[note_id] = note
else:
    all_notes[note_id]['source_keywords'].append("北欧")  # 已存在：追加来源
```

假设 3 个关键词共采集到 198 条，去重后剩 **156 条**，其中 12 条被多个关键词命中。

### 4.2 转为 ViralNote 对象 + 计算互动分数

```python
viral_notes = [ViralNote.from_spider_data(note) for note in all_notes.values()]
```

互动分数计算：
- 图文笔记：`interaction_score = 点赞 + 收藏 + 评论`
- 视频笔记：`interaction_score = 点赞 + 收藏 + 评论 + 分享`

中文数字自动转换：`"2.3万"` → `23000`

### 4.3 降序排序 + 爆款比例筛选

```python
viral_notes.sort(key=lambda x: x.interaction_score, reverse=True)
viral_count = max(1, int(156 × 0.5)) = 78
result = viral_notes[:78]   # 取互动分数 top 78
```

### 4.4 最低样本量检查

```
78 >= 60(min_sample_count) → 通过，进入分析
若不足 → 显示警告，但仍允许继续
若严重不足 → 触发 AutoResupplyService 四阶段补采
```

### 4.5 保存为 JSON 文件

写入 `datas/users/{username}/analysis/viral_notes_20260414_153022.json`：
```json
{
  "collection_time": "20260414_153022",
  "search_keywords": ["巧克力", "北欧", "Fazer"],
  "keyword_statistics": {
    "by_keyword": {"巧克力": 45, "北欧": 38, "Fazer": 22},
    "multi_match_count": 12
  },
  "total_notes": 78,
  "notes": [{...ViralNote.to_dict()...}]
}
```

## 第五阶段：AI 分析

用户点击"开始分析"，`POST /api/viral/analyze`，后台启动 `analyze_viral_notes_task`。

核心编排器 `ViralAnalyzer.analyze_viral_notes()` 按 **11 步**顺序执行：

### 步骤 1-2：统计特征提取

`FeatureExtractor.extract_all_features(notes)` 提取 5 组特征：

| 特征组 | 具体内容 |
|--------|---------|
| 标题特征 | 平均长度、长度分布（4 档）、jieba 分词 top-20 词频、11 种模式命中率（数字开头/感叹号/测评类/教程类等）、emoji 使用率 |
| 内容特征 | 平均长度、长度分布（4 档）、top-20 词频、top-15 标签频率、6 种结构特征（有列表/有步骤/有提示/有警告/有总结/有 CTA） |
| 时间特征 | 发布时间分布（今天/1-3天/4-7天/7天+） |
| 用户特征 | 去重用户数、人均笔记数、top-5 创作者、top-10 IP 归属地 |
| 互动特征 | 平均点赞/收藏/评论、收藏率、互动分布（4 档）、最大/最小值 |

### 步骤 3：封面分析

`CoverAnalyzer.analyze_covers(notes)`：

```
每篇笔记提取封面 URL（图文取 image_list[0]，视频取 video_cover）
  → 10 线程并行下载封面图片
  → 4 线程并行分析每张图：
      → _analyze_colors(image)     # PIL 缩到 200×200，统计 top-10 颜色，归类明暗风格
      → _extract_text(image)       # 调 AI OCR（见下）
      → _analyze_text_layout(text) # 推断文字布局位置
      → _analyze_layout(image)     # 宽高比判断横版/竖版/方形
      → _analyze_visual_elements   # 像素统计推断人物/产品
  → 汇总为 cover_features（颜色/布局/文字/视觉元素统计）
```

**AI OCR 链路**（`AIOCRService.extract_text_from_image`）：
```
PIL.Image → 超 2048px 等比缩小
  → JPEG 压缩（quality 逐步降到 30 直到 ≤ 5MB）
  → base64 编码 → data:image/jpeg;base64,xxx
  → 调用多模态 AI API（如 qwen-vl-plus）
  → prompt: "提取所有可见文字，每行一个文字块"
  → 解析返回文本，过滤空结果
```

### 步骤 4-5：全图 OCR + 场景分析

对图文笔记的所有图片（最多 9 张/篇）做同样的 OCR，汇总产出 `all_images_ocr`（全图词频、封面与非封面对比）。

场景分析用 AI 识别每篇笔记的场景类型（居家/户外/办公等）和风格方向。

### 步骤 6：AI 深度分析（主分析）

`ViralAnalyzer._analyze_with_ai()`：

```
取前 3 篇高互动笔记作为样本（超 1000 字截取首 500 + 尾 200）
  → 检索知识库（双轨制）：
      → JSON 配置：根据关键词匹配领域（如 "hair_care"），获取规则文本
      → RAG 检索：ChromaDB 向量相似度搜索，返回 top-5 文档片段
  → 构建 prompt：
      系统角色: "小红书爆款内容分析专家"
      内容: 知识库 + 统计特征 + 笔记样本 + 分析要求
  → 调用大模型 API（DeepSeek/通义千问）
      model: deepseek-chat, temperature: 0.7, max_tokens: 3000, timeout: 300s
  → 解析响应（支持 JSON/代码块/纯文本三种格式回退）
  → 写入 viral_model['ai_insights']
```

### 步骤 7：多模态批量分析

`MultimodalAnalyzer.analyze_notes_batch()`：

```
逐篇笔记顺序处理（每篇间隔 3 秒防 QPM 限流）：
  → 获取最多 9 张图片 URL
  → 构建多模态消息：文字（标题+正文前500字+互动数据）+ 图片 URL
  → 调 AI API 分析图文结合的内容策略
  → 解析 JSON 响应（兼容 4 种格式：纯 JSON / ```json / 裸 {} / <think> 标签剥离）
  → 汇总为 multimodal_insights
```

### 步骤 8：视频分析（如有视频笔记）

`VideoEnhancedAnalyzer.analyze_batch_videos()`：

```
每 2 个视频一组并发：
  → 顶层统一下载（proxy 模式）：
      download_manager.acquire(url, backup_urls, note_id)
      去重（同 URL 只下载一次）+ 引用计数 + 原子写入（tmp → rename）
      HEAD 预检大小 → 超 7MB 自动降级到 URL 模式

  → 并行 4 个任务（asyncio.gather）：
      1. 封面分类：AI 识别封面主类别（人物/产品/场景/文字等）
      2. 标题分类：AI 识别标题策略（痛点型/种草型/教程型等）
      3. 时间轴分析：AI 提取 7 个关键数据点
         - 产品首次出现时间
         - 产品使用/演示时间
         - 正文开始时间
         - 内容类型、引入方式、产品引出方式、植入方式
      4. 音画同步分析（可选）：ffmpeg 抽帧 + ASR 语音识别

  → 全部完成后释放下载引用
```

**视频 AI 分析的模式选择**（`VideoAIAnalyzer`）：

```
URL 模式（默认）：
  → 优选 _130.mp4（H.264 压缩版，约 3-4MB）
  → 直接传视频 URL 给 AI API
  → 最多试 3 个 URL，失败换下一个
  → 全部失败 → 降级为元数据分析（只用标题+描述推断）

Proxy 模式：
  → 本地下载视频 → HEAD 预检大小
  → ≤ 7MB → base64 编码 → 传给 AI API
  → > 7MB → 自动切到 URL 模式
  → 7MB 限制原因：base64 膨胀 ×1.33 ≈ 9.3MB < 通义千问 10MB API 限制
```

### 步骤 9：AI 综合推理

`SynthesisService.synthesize_final_model()`：

```
汇总所有分析结果（统计特征 + 封面 + 视频 + 知识库 + AI 分析）
  → 构建综合推理 prompt（viral_model_prompts.build_viral_model_prompt）
  → 调 AI API：temperature 0.7, max_tokens 4000
  → DeepSeek/OpenAI 加 response_format={"type": "json_object"}
  → 不支持的模型降级为 prompt 末尾追加 JSON 强制要求
  → 解析为最终爆文模型 → viral_model['final_delivery']
```

### 步骤 10-11：保存结果

```
ViralAnalysisResult 包装所有数据
  → save_to_file("viral_analysis_20260414_153022.json")
  → 更新任务状态为 "analyzed"
```

## 第六阶段：Excel 报告导出

用户点击"下载报告"，调用 `export_to_excel()`，生成 **9 个 Sheet** 的 Excel 文件：

| Sheet | 内容来源 |
|-------|---------|
| 总览与爆文模型 | `final_delivery`（综合推理结果）+ 成功案例（含 note_url 超链接）+ 发布检查清单 |
| AI 深度分析 | `ai_insights` + `multimodal_insights` |
| 产品分析 | 产品引出时机、营销场景、引出方式统计 |
| 场景方向分析 | 场景类型分布、方向建议 |
| 标题分析 | 长度分布图表、词频、11 种模式命中率、emoji 使用率 |
| 内容分析 | 长度分布、词频、标签频率、6 种结构特征 |
| 封面与配图分析 | 颜色/布局/文字分析 + 全图 OCR 词频 |
| 视频 AI 深度分析 | 7 维时间轴 + 封面/标题分类 + 视频爆文模型 |
| 原始数据 | 所有笔记明细（12 列：序号/标题/内容/四项互动/用户/类型/链接/时间） |

最终用户下载到 `viral_report_20260414_153022.xlsx`。

## 完整数据格式流转总结

```
用户输入关键词
  → POST /api/viral/search（JSON 请求体）
  → ViralNoteCollector 多关键词 × 三维度采集
    → XHS_Apis（带 JS 签名）→ 小红书 API → 原始 JSON
    → handle_note_info() → 扁平字典
    → ViralNote.from_spider_data() → dataclass（含 interaction_score）
  → 去重（note_id）→ 排序（interaction_score 降序）→ 筛选（top N%）
  → 保存 viral_notes_*.json

  → POST /api/viral/analyze
  → FeatureExtractor → 5 组统计特征
  → CoverAnalyzer → 封面颜色/布局/OCR
  → MultimodalAnalyzer → 图文联合 AI 分析
  → VideoEnhancedAnalyzer → 视频 4 维并行分析
  → KnowledgeRetriever → JSON 规则 + RAG 文档
  → ViralAnalyzer → AI 深度分析（prompt + 大模型）
  → SynthesisService → AI 综合推理 → 最终爆文模型
  → 保存 viral_analysis_*.json

  → ExportService → 9 Sheet Excel 报告
  → 用户下载 viral_report_*.xlsx
```
