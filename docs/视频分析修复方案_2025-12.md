# 视频分析模块修复方案

> 版本：v1.0
> 日期：2025-12-30
> 状态：待实施

## 问题背景

根据运行日志分析，视频分析模块存在以下问题：

| 问题 | 影响 | 日志表现 |
|------|------|----------|
| 模型无法访问小红书CDN | 87.5%时间轴数据缺失 | `API调用异常:` (空) |
| 并发过高 | API频繁超时/限流 | 38次API调用异常 |
| 时间轴无多URL兜底 | 单URL失败即失败 | 19次回退到元数据分析 |
| deepseek-reasoner不适合分类 | 标题分类返回empty | 16次AI分类结果无效 |
| JSON解析失败 | 爆文模型不完整 | 多策略修复仍失败 |
| Excel合并单元格写入 | 产品分析表警告 | MergedCell报错 |

### 根本原因分析

**小红书CDN防盗链机制**：
- 小红书视频URL需要带 `Referer: https://www.xiaohongshu.com/` 才能访问
- 本地验证时带Referer → 通过
- 但发给阿里云API时，模型方访问URL时不带Referer → 403失败
- 导致大量视频分析回退到元数据分析，无法获取真实时间点数据

## 修复方案总览

| 优先级 | 问题 | 修复文件 | 修复内容 |
|--------|------|----------|----------|
| **P0-1** | 模型无法访问小红书CDN | `video_ai_analyzer.py` | 增加 `VIDEO_SOURCE_MODE=url\|proxy\|upload`，优先走可公网访问URL |
| **P0-2** | API调用异常日志为空 | `video_ai_analyzer.py` | 记录异常类型+repr，补充超时/网络异常重试 |
| **P0-3** | 并发过高导致超时 | `video_ai_analyzer.py` | 全局 semaphore 限制所有视频分析调用 |
| **P0-4** | 时间轴无多URL兜底 | `video_timeline_analyzer.py` + `video_enhanced_analyzer.py` | `analyze_timeline` 透传 `video_urls` |
| **P1-1** | reasoner不适合分类 | `video_ai_analyzer.py` + `video_title_classifier.py` + `.env` | `analyze_text` 增加 model 参数，标题分类用 `TITLE_MODEL_NAME` |
| **P1-2** | 标题格式不稳定 | `video_title_prompts.py` | 强制固定格式 `Result_主类,子类` |
| **P2-1** | 综合推理JSON失败 | `synthesis_service.py` | 根据服务类型开关 `response_format`，否则提示词强制JSON |
| **P2-2** | 合并单元格写入错误 | `export_service.py` | 统一"先写值再merge / safe_set_cell_value" |
| **P3** | 缺失败样本记录 | `export_service.py` | 导出里加 `analysis_status` / `error_message`（字段已存在） |

## 详细修复方案

### P0-1：视频源可用性

**文件**：`viral_agent/services/video_ai_analyzer.py`

**新增配置**（`.env`）：
```env
# 视频源处理模式
VIDEO_SOURCE_MODE=url           # url/proxy/upload
VIDEO_MAX_CONCURRENT=2          # 同时处理视频数
VIDEO_DOWNLOAD_TIMEOUT=60       # 下载超时(秒)
VIDEO_MAX_SIZE_MB=50            # 单个视频大小限制
```

**行为说明**：
- `url`：原样使用视频URL（如果可访问）
- `proxy`：本地下载（带Referer）→ 上传到可公网访问存储（OSS等）→ 用新URL分析
- `upload`：调用模型方文件上传接口，拿 file_id/input_file（按厂商能力）

**注意**：Base64仅作为"兼容但不推荐"的兜底，不作为主方案。原因是Base64视频体积大、厂商兼容性不稳定。

### P0-2：异常日志增强 + 重试

**文件**：`viral_agent/services/video_ai_analyzer.py` 的 `_call_ai_api` 方法

**修改内容**：
```python
except asyncio.TimeoutError as e:
    logger.error(f"API调用超时: {timeout}s | {type(e).__name__}")
    last_error = f"timeout_{timeout}"
    continue  # 超时可重试
except aiohttp.ClientError as e:
    logger.error(f"API网络异常: {type(e).__name__}: {repr(e)}")
    last_error = f"network_{type(e).__name__}"
    continue  # 网络异常可重试
except Exception as e:
    logger.error(f"API调用异常: {type(e).__name__}: {repr(e)}")
    return f"API调用异常: {type(e).__name__}"
```

### P0-3：全局并发限制

**文件**：`viral_agent/services/video_ai_analyzer.py`

**修改内容**：

在 `__init__` 中添加：
```python
self.video_semaphore = asyncio.Semaphore(int(os.getenv("VIDEO_MAX_CONCURRENT", "2")))
```

在 `analyze_video` 或 `_analyze_video_directly` 入口处包装：
```python
async with self.video_semaphore:
    return await self._call_ai_api(...)
```

**效果**：视频产品分析、时间轴分析、其他视频调用都被统一限流。

### P2-2：合并单元格写入

**文件**：`viral_agent/services/export_service.py`

**修改内容**：统一使用"先写值再merge"模式
```python
# 修改前（报错）
ws.merge_cells(start_row=row, start_column=col, end_row=row, end_column=col+2)
ws.cell(row=row, column=col+1).value = "xxx"  # MergedCell报错

# 修改后
ws.cell(row=row, column=col).value = "xxx"  # 先写入左上角单元格
ws.merge_cells(start_row=row, start_column=col, end_row=row, end_column=col+2)  # 再合并
```

或使用安全写入函数：
```python
def safe_write_merged_cell(ws, row, col, value, merge_cols=1):
    """安全写入可能被合并的单元格"""
    cell = ws.cell(row=row, column=col)
    if not isinstance(cell, MergedCell):
        cell.value = value
    if merge_cols > 1:
        ws.merge_cells(start_row=row, start_column=col, end_row=row, end_column=col+merge_cols-1)
```
