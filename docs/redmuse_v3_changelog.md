# v3 方案基于业务方案的调整记录

基于 `docs/redmuse业务方案.md` 的逐段分析，记录所有需要调整的点和调整结论。

## 核心变更清单

### 1. 产品架构：从"搜索框模式"转向"Canvas 模式"

业务方案原文：

> 从SEO逻辑的对话框转向Canvas模式。在一个分屏界面中，左侧保留对话流（LUI）用于输入意图、下达指令，而右侧开启一个独立的、可持久化的作业空间（GUI）。

调整：

- 前端主工作台从"输入框 → 等待 → 结果展示"改为"左侧对话流 + 右侧结构化画布"
- 对话区负责输入意图和追加指令
- 画布区展示爆文模型，支持模块级操作（折叠/展开/重新生成/深入分析）
- 用户可以通过对话追加指令来修改画布上的特定模块
- 所有 UI 原型需要重新设计

### 2. 分析维度：从"统一特征提取"扩展为"三维洞察"

业务方案原文：

> 洞察：行业分析、竞品分析、本品分析

调整：

- SemanticAnalysisAgent 需要拆分出三个子分析维度：
  - 行业分析：该品类在小红书的整体市场情况和爆文特征
  - 竞品分析：同品类其他品牌的内容策略和爆文特征
  - 本品分析：用户指定品牌/产品的内容表现和机会点
- InputParserAgent 需要从用户输入中识别"品牌/产品名"（用于区分本品和竞品）
- ContentStrategyAgent 的输出结构需要包含三维洞察

### 3. 输出结构：从"AI洞察→爆文模型→数据"调整为"框架→洞察→原始数据"

业务方案原文：

> 参考业务模版，按照"框架——洞察——原始数据"的形式编排。

调整：

- 画布区的内容顺序调整为：
  1. 爆文模型框架（方法论 + 案例支撑）
  2. 多维洞察（行业/竞品/本品）
  3. 原始数据（交叉验证依据）
- Excel 导出也按此顺序编排

### 4. 爆文模型需要"方法论 + 案例支撑"双层

业务方案原文：

> 爆文模型框架（方法论）+ 爆文模型详例（方法+案例支撑）

调整：

- 当前 v3 只输出方法论（标题策略、内容结构等）
- 需要增加"案例支撑"层：每个方法论点都要有对应的真实爆文案例佐证
- 案例来自采集到的原始数据，由 Agent 自动匹配

### 5. 产品定位措辞对齐

业务方案原文：

> RED MUSE只提供洞察和框架，始终坚持AI赋能，始终坚守人的灵动的价值

调整：

- 所有 UI 文案中避免"自动生成内容"类措辞
- 使用"洞察"、"框架"、"灵感中枢"、"方向支点"
- 画布区的标题不叫"AI 生成报告"，叫"爆文洞察与框架"
- 强调"赋能而非替代"的定位

### 6. 合规性：不直接复用原始数据

业务方案原文：

> 不直接复用原始数据，仅提取规律性特征

调整：

- 原始数据区块的定位从"数据展示"调整为"交叉验证依据"
- 明确标注"以下数据仅用于验证模型结论，不建议直接用于内容创作"
- 导出 Excel 中原始数据 Sheet 标注为"验证参考"

### 7. 基础数据库：10 品类预置

业务方案原文：

> 规模化采集10个常用品类下各100篇爆款笔记，形成基础数据库

调整：

- 定时爬虫预热机制中增加"基础品类库"概念
- 预置 10 个品类：美妆护肤、穿搭时尚、美食探店、母婴育儿、家居好物、健身运动、数码科技、宠物、旅行、教育
- 每个品类初始化 100 篇爆文数据
- 系统设置页增加"基础品类库"管理

### 8. 未来扩展预留

业务方案中提到但不在本次实现的：

- 行业全域洞察（接入站外数据）
- 潜力笔记诊断与投放
- 笔记自动生产与发布

架构上预留：

- Agent 架构支持新增节点而不改主流程
- 数据模型预留外部数据源字段
- 画布区预留"诊断"模块位置
