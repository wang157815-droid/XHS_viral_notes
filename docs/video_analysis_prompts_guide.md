## 1. 视频分析流程概览

### 1.1 整体架构

```
爆款笔记采集
     │
     ▼
判断笔记类型（图文 / 视频）
     │
     ├── 图文笔记 → 图文分析流程（封面OCR、内容分析等）
     │
     └── 视频笔记 → 视频分析流程 ← 本文档重点
                    │
                    ▼
              ┌─────────────────────────────────────────┐
              │        VideoEnhancedAnalyzer            │
              │    （增强型视频分析器，统一入口）           │
              ├─────────────────────────────────────────┤
              │  ① 封面分析 (VideoCoverClassifier)       │
              │  ② 标题分析 (VideoTitleClassifier)       │
              │  ③ 时间轴分析 (VideoTimelineAnalyzer)    │
              │     └→ 7个关键数据点提取                  │
              │     └→ 调用 AI 模型分析视频内容           │
              └─────────────────────────────────────────┘
                    │
                    ▼
              导出 Excel 报告（视频AI深度分析工作表）
```

### 1.2 核心分析维度

视频分析提取 **7 个关键数据点**：

| 编号 | 数据点 | 说明 | 示例 |
|------|--------|------|------|
| A | 产品出现时间 | 产品首次在画面中展示的时间 | 30s |
| B | 产品使用时间 | 博主开始实际使用产品的时间 | 60s |
| C | 干货开始时间 | 实用内容/教程正式开始的时间 | 45s |
| D | 大类-类型 | 视频内容分类 | 干货教程-手法干货 |
| E | 内容切入点 | 视频如何引入主题 | 熬夜垮脸 |
| F | 产品引出方式 | 博主如何引入产品 | 自用分享 |
| G | 产品植入方式 | 产品如何融入视频内容 | 干货手法中植入 |

### 2.2 PRD 合规率计算逻辑

```python
# PRD标准
产品出现时间 ≤ 30秒
干货开始时间 20-40秒
产品讲解时间 40-60秒

# 综合合规分数（加权平均）
权重 = [0.4, 0.35, 0.25]  # 产品出现最重要
综合分数 = 0.4×产品≤30s率 + 0.35×干货20-40s率 + 0.25×讲解40-60s率
```

## 4. 完整提示词模板

### 4.1 视频时间轴分析提示词（完整版）

```markdown
您是一位资深社交媒体内容分析师，专精于美妆护肤领域的短视频分析。

【重要验证步骤】在分析前，请先确认：
1. 您是否成功读取并观看了视频？如果没有，请回答"无法读取视频"
2. 视频的实际时长是多少秒？（必须准确回答）
3. 如果视频时长小于10秒，所有时间点必须在视频时长范围内

现需要您观看提供的小红书视频，并基于真实视频内容提取7个关键数据点。
这些数据点需要通过实际观看才能准确判断，不能仅凭标题或描述推测。

【关键原则】：
- 所有时间点(A/B/C)必须 < 视频实际时长
- 如果无法确定某个时间点，使用"/"标记
- 严禁推测或编造时间点
- 请根据视频实际内容选择分类，不要受标题影响过度推测

需提取的7个关键数据点及详细说明：

1. 产品出现时间(A)
记录产品首次在画面中展示的确切时间点（单位：秒）
示例：29s、75s、115s
如未出现产品，标记为"/"

2. 产品使用时间(B)
记录博主开始实际使用/演示产品的时间点（单位：秒）
示例：30s、52s、107s
如未使用产品，标记为"/"

3. 干货开始时间(C)
记录实用内容/教程/技巧正式开始的时间点（单位：秒）
示例：20s、45s、98s
如无干货内容，标记为"/"

4. 大类-类型(D)
根据视频内容判断分类：

大类可能为：
- 单品推荐：重点推荐单个产品
- 干货教程：分享实用技巧或方法
- 剧情：讲故事或情景表演
- vlog/沉浸式：生活记录或沉浸式体验
- 合集：多产品推荐
- 系列推荐：同品牌系列产品推荐
- 漫画：动画或漫画形式
- 美食：美食相关内容
- 测评：产品测试对比

类型可能为：
- 单品推荐：专注于单一产品
- 手法干货：展示按摩、拨筋、刮痧等技巧
- 剧情单推：通过剧情推荐产品
- vlog：日常记录形式
- 伪合集：看似合集但重点推荐特定产品
- 品牌系列产品：同品牌多产品推荐
- 变装：前后形象变化
- 动画剧情：动画形式展现剧情
- 女性成长：关注女性成长话题
- 大促单推：节日大促销推荐
- 轻科普单推：轻度科普知识
- 多种用法：展示产品多种使用方法
- 妆教：化妆教程
- 内调外养：内外兼修的养护方法

组合示例：干货教程-手法干货、单品推荐-单品推荐、剧情-剧情单推

5. 内容切入点(E)
视频如何开始引入主题：
- 问题切入：指出具体皮肤/妆容问题
- 场景切入：季节、场合、生活场景
- 效果切入：展示预期效果或对比
- 年龄切入：特定年龄段的护理需求
- 经验切入：个人护肤/化妆经验分享

6. 产品引出方式(F)
博主如何引入产品：

基于问题引出：
- 肌肤问题（指出具体问题后引出）
- 护理需求（指出护理需求后引出）
- 妆容需求（指出化妆需求后引出）

基于体验引出：
- 自用分享/自用好物
- 护肤/化妆经验
- 他人推荐
- 经验分享

直接引出：
- 直接带出（无过渡直接展示）
- 成分引出（通过成分优势引出）
- 功效引出（通过功效卖点引出）

7. 产品植入方式(G)
产品如何融入视频内容：

内容植入型：
- 流程中植入产品（在整体流程中自然展示）
- 干货手法中植入（在教学过程中使用）
- 干货流程中植入（作为流程一部分）
- 护理按摩植入（按摩/护理过程中使用）

直接展示型：
- 手持口播（手持产品直接讲解）
- 使用方法中植入（展示具体使用方法）
- 妆教中植入（化妆教程中使用）

#输出格式要求：
请严格按照以下格式输出分析结果，用英文逗号分隔7个数据点：
Result_A,B,C,D,E,F,G

示例：
例1：Result_30s,60s,45s,单品推荐-单品推荐,熬夜垮脸,自用分享,手持口播
例2：Result_15s,22s,18s,干货教程-手法干货,肌肤问题,护理经验,干货手法中植入
例3：Result_48s,/,52s,剧情-剧情单推,紧致提升,护理需求,流程中植入产品

如某项内容无法判断或不存在，请使用"/"标记。

#重要提示：
- 数据点必须完全基于观看视频得出，不能仅凭标题推测
- 时间点请精确到秒，使用数字+s表示
- 产品出现和使用可能为同一时间，也可能有先展示后使用的情况

【视频信息】
视频URL: {video_url}
视频标题: {title}
视频描述: {description}
```

### B.6 已知问题与原因分析

#### 问题1：平均互动显示为0

**现象**：切入方式、植入方式的"平均互动"列全部显示为0，但单个视频的互动分数是有值的（如458160）。

**原因**：字段名不匹配（代码Bug）

```python
# 代码期望的字段名（video_timeline_analyzer.py:416）
interaction = note.get('liked_count', 0) + note.get('collected_count', 0)

# 但实际数据的字段名可能是：
# - 'liked' 而不是 'liked_count'
# - 'collected' 而不是 'collected_count'
# - 或嵌套在 'interact_info' 对象里
```

当 `note.get('liked_count', 0)` 找不到字段时，返回默认值 `0`，导致所有互动计算结果都是 `0+0=0`。

**结论**：这是**代码Bug**，不是数据读取失败。需要修复字段名映射逻辑。

**修复建议**：
```python
# 兼容多种字段名
interaction = (
    note.get('liked_count') or
    note.get('liked') or
    note.get('interact_info', {}).get('liked_count') or
    0
) + (
    note.get('collected_count') or
    note.get('collected') or
    note.get('interact_info', {}).get('collected_count') or
    0
)
```

#### 问题2：部分视频返回"无法读取视频"

**现象**：13个视频中有2个（15.4%）返回"无法读取视频"，没有分析结果。

**原因**：这是**AI模型的限制**，不是提示词问题。

提示词中设计了验证步骤：
```markdown
【重要验证步骤】在分析前，请先确认：
1. 您是否成功读取并观看了视频？如果没有，请回答"无法读取视频"
```

这是**防止AI幻觉的保护机制**。当AI返回"无法读取视频"时，可能的原因：

| 原因 | 说明 |
|------|------|
| 视频URL过期 | 小红书视频URL中的 `xsec_token` 有时效性，采集后一段时间可能失效 |
| 视频格式不兼容 | AI模型不支持该视频的编码格式 |
| 视频无法在线访问 | 需要登录、地域限制、防盗链等 |
| AI模型网络限制 | 部分AI服务商无法访问外部视频URL |

**结论**：这**不是Bug**，而是正常的兜底行为。如果不加这个验证步骤，AI可能会根据标题编造时间点，产生更严重的数据质量问题。

**优化建议**：
1. 采集后尽快进行分析，减少URL过期
2. 分析前增加视频URL有效性预检
3. 提供多个备选视频URL（系统已支持多源重试机制）
