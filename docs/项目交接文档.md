|------|------|
| 项目名 | Spider_XHS（小红书爆文分析系统） |

## 三、核心数据流

### 3.1 数据采集流程

```
用户输入关键词（Web UI / 命令行）
    ↓
viral_collector.py 多关键词三维度采集（点赞/评论/收藏）
    ↓
xhs_pc_apis.py 调用小红书搜索/笔记详情 API
    ↓
xhs_util.py → execjs → static/xhs_xs_xsc_56.js（生成请求签名）
    ↓
HTTP 请求 → 小红书服务器 → 返回 JSON
    ↓
data_util.py 解析笔记数据 → 去重 → 爆款筛选
```

### 3.2 AI 分析流程

```
采集到的爆款笔记列表
    ↓
feature_extractor.py 统计特征提取
    ↓
cover_analyzer.py / video_enhanced_analyzer.py（图文/视频分析）
    ↓
knowledge_retriever.py 检索知识库（JSON 配置 + RAG 文档）
    ↓
viral_analyzer.py 构建 prompt → 调用 AI API（DeepSeek/通义千问/GLM）
    ↓
export_service.py 生成 Excel 报告
```

### 3.3 认证流程

```
用户打开 Web 界面 → 登录（用户名/密码）
    ↓
auth_service.py 签发 JWT token
    ↓
需要采集数据时 → 扫码获取小红书 Cookie
    ↓
qrcode_login_service.py（Playwright 渲染二维码）
    ↓
用户手机扫码确认 → 获取 Cookie
    ↓
cookie_validator.py 三层验证（字段完整性 + API 轮询 + 数据非空）
```

## 六、部署相关

### 生产部署（Docker）

```bash
# 构建并启动
docker compose up -d --build

# 查看日志
docker compose logs -f spider-xhs

# 重启
docker compose restart spider-xhs

# 完全重建
docker compose down && docker compose up -d --build
```

### 关键注意事项

1. **JS 签名文件是核心资产**：`static/` 目录下的 JS 文件负责生成小红书 API 请求签名，小红书会不定期更新加密算法，届时需要更新这些文件
2. **Cookie 会过期**：需要定期重新扫码获取，或通过 Web 界面扫码
3. **AI API 成本**：推荐使用 DeepSeek（成本最低）或 GLM-4-flash（免费）
4. **Playwright 镜像**：Docker 中使用淘宝镜像下载 Chromium，版本锁定为 1.52.0

## 八、踩坑记录（重要）

> 以下是开发过程中遇到的关键问题，新人接手后大概率会再次遇到。

### 坑 1：小红书限流是"软拒绝"（不报错，只返空数据）

- **现象**：采集到第三维度（收藏）时，笔记详情全部为空，但 API 返回 `success=True`
- **原因**：前两维度累计 ~72 次请求/75 秒，触发限流。限流不返回错误码，而是返回 `success=True, items=[]`
- **解决**：维度间冷却 10 秒（`DIMENSION_COOLDOWN` 环境变量可调）+ 连续空结果时自适应降速 + 重试
- **教训**：**永远不要只看 `success` 字段**，必须同时检查返回数据是否非空

### 坑 2：Cookie 的 `success=True` 不代表有权限

- **现象**：半有效 Cookie（有 a1 但无 web_session）被验证为"有效"，实际采集时拿不到数据
- **原因**：小红书对半有效 Cookie 返回 `success=True, msg=None, data=[]`，意思是"请求格式正确"而非"有权限"
- **解决**：三层验证（字段完整性 → 多关键词 API 轮询 → 数据非空检查）
- **教训**：API 的 success 含义因平台而异，必须做数据层验证

### 坑 3：JS 签名文件里的同形异义字符

- **现象**：`globalThis.Infinity` 变成 `globalThis.锟斤拷nfinity`，签名计算 SyntaxError
- **原因**：`xhs_xs_xsc_56.js` 中混入 18 个希腊大写 Iota（U+0399），和拉丁 I 肉眼完全一样，Node.js v22 通过 stdin 管道时 UTF-8 编码损坏
- **解决**：用 `unicodedata.name()` 逐字符检查，替换为纯 ASCII
- **教训**：更新 JS 签名文件后，必须检查是否混入非 ASCII 字符。可用 `python3 -c "import re; print(re.findall(r'[^\x00-\x7f]', open('file.js').read()))"`

### 坑 4：uvloop + nest_asyncio 冲突导致启动崩溃

- **现象**：Docker 中 `viral_app.py` 启动立即崩溃，`RuntimeError: There is no current event loop`
- **原因**：`uvicorn[standard]` 自带 `uvloop`，它在 import 时接管 event loop policy。而项目中 `nest_asyncio.apply()` 在模块导入时就执行了，两者冲突
- **解决**：启动前 `asyncio.set_event_loop_policy(None)` 重置 + uvicorn 配置 `loop="asyncio"`
- **教训**：`uvicorn[standard]` 和 `nest_asyncio` 不能共存于同一 event loop policy，要么去掉 uvloop，要么去掉 nest_asyncio

### 坑 5：Playwright Docker 构建失败

- **现象**：`playwright install chromium --with-deps` 在 Docker 中 404 或字体包找不到
- **原因**：两个独立问题叠加
  1. 官方 CDN（cdn.playwright.dev）国内服务器无法访问 → 改用淘宝镜像
  2. Debian Trixie 重命名了字体包（`ttf-unifont` → `fonts-unifont`）→ 手动安装依赖，Playwright 只下载浏览器
  3. 最新 Playwright 对应的 Chrome 版本淘宝镜像可能未同步 → 锁定 playwright==1.52.0
- **解决**：见 Dockerfile 中的注释
- **教训**：Playwright 版本、Chrome 版本、镜像同步、系统包名四者要对齐

### 坑 6：视频 proxy 模式大文件 API 报错

- **现象**：视频经 base64 编码后传给 AI API 报错
- **原因**：通义千问 API 有 10MB 请求体限制，视频 base64 编码膨胀 ×1.33，所以原始视频需 ≤ 7.5MB
- **解决**：超过阈值自动降级到 URL 模式（`VIDEO_PROXY_MAX_MB` 可配置，默认 7）
- **教训**：这不是 bug，是 API 约束。proxy 模式对大视频天然不适用，URL 模式降级是正常路径
